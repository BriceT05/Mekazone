## 5. Stratégie responsive

- Art direction : deux variants par bannière (desktop/mobile) chargés via `getImageProps` + `<picture>` avec media queries, comme le Hero. Une seule requête par viewport.
- B2 : desktop 600×900 (portrait) → mobile 800×400 (paysage). Changement d'aspect ratio majeur : le recadrage est déjà validé (masters distincts).
- B3 : desktop 1920×480 → mobile 1080×540. Changement d'aspect ratio majeur également.
- Coins arrondis conservés sur tous les breakpoints (`rounded-xl`).
- Ombres conservées (`shadow-card` → `shadow-elevated` au hover si interactif).
- Pas de débordement horizontal : images en `w-full`, `object-cover` dans un conteneur à ratio fixe.

## 7. Accessibilité

- **B2 et B3 (images brutes + overlay HTML)** : structure sémantique `section`/`figure` avec `aria-labelledby`. Texte overlay réel dans le DOM (accessible) pour les deux bannières. `alt` court et descriptif sur l'image (pas de texte long). Bouton CTA désactivé avec `aria-disabled="true"` et `tabIndex={-1}` (pas de lien fictif).
- **Contraste** : texte blanc sur photo moteur (B3) — vérifier le contraste ≥ 4,5:1. Si insuffisant, ajouter un scrim sombre (`bg-noir/40`) derrière le texte. B2 : photographie naturellement sombre (sujet sur fond sombre) ; aucune analyse pixel ne montre de scrim intégré dans les pixels — tout assombrissement pour la lisibilité doit être appliqué par le composant en CSS (`bg-noir/40` ou équivalent) si le contraste l'exige, à vérifier à l'implémentation.
- **Focus clavier** : si la bannière est non interactive, pas de `tabIndex`. Si un CTA est présent et désactivé, `tabIndex={-1}`.
- **prefers-reduced-motion** : toute animation d'entrée (fade/slide) désactivée sous `motion-reduce:`. Les bannières statiques n'ont pas d'animation par défaut.
- **Alt vide** uniquement si la bannière est purement décorative (non recommandé ici car le contenu promotionnel est informatif).

## 8. Interactions

- **Aucun lien commercial fictif.** Les bannières ne créent pas de route inexistante.
- Les CTA overlay (B2 et B3) sont **désactivés** (`aria-disabled="true"`, `tabIndex={-1}`, pas de `<Link>`), avec un style visuellement atténué (opacité 60 %) pour signaler l'indisponibilité, cohérent avec le pattern D2.3. Aucun CTA fictif n'est interactif ; le CTA désactivé n'est pas un élément de l'image (les photographies B2 sont brutes, sans texte incrusté).
- Alternative : retirer le CTA de l'overlay HTML pour B2 et B3 et garder uniquement le texte informatif.
- Réactivation future : passer la constante `PROMO_LINKS_ENABLED` à `true` et restaurer les `<Link>` (pattern D2.3).
