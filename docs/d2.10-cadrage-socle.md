## 1. Objectif

Livrer le **socle technique commun** des futures pages institutionnelles, sans créer ni publier aucune des sept pages, et sans écrire la moindre affirmation commerciale ou juridique.

Le socle doit rendre possible, plus tard, l'ajout d'une page en créant un seul fichier `page.tsx` et une entrée de données, sans toucher au chrome, au gabarit ni au SEO technique.

## 2. Périmètre strict

### 2.1 Dans le périmètre (D2.10)

1. Chrome partagé dans le layout racine (`SiteHeader`, `<main id="contenu">`, `SiteFooter`).
2. Lien d'évitement (« Aller au contenu ») comme premier élément focusable.
3. Page `not-found.tsx` en français, avec chrome et liens utiles.
4. Gabarit éditorial partagé (groupe de routes `(institutionnel)/layout.tsx`).
5. Composants éditoriaux communs : `PageHeader`, `Breadcrumb`, `Prose`, `InfoPanel`, `RelatedLinks` (voir § 6).
6. Métadonnées de base : `title.template`, descriptions par défaut, `metadataBase` **conditionné**, canoniques **conditionnées**.
7. `sitemap.ts` et `robots.ts` (routes publiées uniquement ; aucune route publiée au départ).
8. Registre de publication vide (`src/data/institutional/index.ts` + `src/types/institutional.ts`).
9. Correctif minimal de `SiteHeader.tsx` pour les ancres inter-routes (J13, périmètre strict § 7).
10. Tests et captures de non-régression de l'accueil.

### 2.2 Hors périmètre (interdit dans D2.10)

- Création ou publication de l'une des sept pages institutionnelles.
- Tout texte commercial, juridique, FAQ, coordonnée, délai, tarif, garantie.
- Tout formulaire, embed tiers, carte, chat, newsletter.
- Toute dépendance (`package.json` inchangé).
- Toute migration, table ou policy Supabase.
- Tout changement de Header au-delà du correctif d'ancre (§ 7), de Footer, de logo, de favicon, de Hero, de catégories, de bannières, de produits.
- Tout commit/push au-delà du commit de publication de ce cadrage (si demandé).

## 4. Architecture technique

### 4.1 Chrome partagé (option A)

Déplacer dans `src/app/layout.tsx` :

```tsx
// proposition — non implémentée
<body>
  <SiteHeader />
  <main id="contenu" tabIndex={-1}>{children}</main>
  <SiteFooter />
</body>
```

- `src/app/page.tsx` ne garde que les quatre sections de l'accueil (le chrome est retiré).
- **Invariant** : un seul `<main>`, un seul `contentinfo`, un seul `h1` par page.
- Lien d'évitement en tout premier élément focusable, cible `#contenu`.

**Fichiers protégés touchés** : `src/app/layout.tsx` (autorisé, hors liste protégée), `src/app/page.tsx` (autorisé). `SiteHeader.tsx` et `SiteFooter.tsx` sont touchés uniquement via le correctif J13 pour le Header ; le Footer n'est pas modifié.

### 4.2 Groupe de routes éditorial

```
src/app/
├─ layout.tsx
├─ page.tsx
├─ not-found.tsx
├─ sitemap.ts
├─ robots.ts
└─ (institutionnel)/
   └─ layout.tsx          gabarit éditorial (PageHeader, Breadcrumb, Prose, RelatedLinks)
```

Le groupe `(institutionnel)` ne crée aucune URL. Aucune `page.tsx` n'y est ajoutée en D2.10.

### 4.3 Composants créés (serveur, aucune dépendance)

| Composant | Rôle | Props minimales |
|---|---|---|
| `PageHeader` | `h1`, chapô, eyebrow, date de mise à jour | `title`, `intro?`, `eyebrow?`, `updatedAt?` |
| `Breadcrumb` | fil d'Ariane accessible | `items: {label, href?}[]` |
| `Prose` | typographie longue lecture | `children`, `size?` |
| `InfoPanel` | encart d'information / avertissement | `title?`, `tone`, `children` |
| `RelatedLinks` | liens croisés en bas de page | `links: {label, href}[]` |

Emplacement proposé : `src/components/content/`. Aucun de ces composants ne contient de texte commercial.

### 4.4 404 MEKAZONE

`src/app/not-found.tsx` : français, avec chrome, `h1` (« Page introuvable »), message factuel, liens vers l'accueil et les catégories (ancres existantes), statut HTTP 404, `noindex` implicite.

### 4.5 Métadonnées sans domaine confirmé

- `title.template: "%s — MEKAZONE"` et `default` conservé pour `/`.
- `description` par défaut factuelle et sans promesse.
- **`metadataBase` : non émis** tant que `NEXT_PUBLIC_SITE_URL` n'est pas confirmé. Aucune URL absolue inventée.
- **Canoniques : non émises** tant que l'origine officielle n'est pas confirmée (résolution de la contradiction signalée par l'audit).
- `openGraph` par défaut : `type: "website"`, image `public/og/og-default.png` (1200 × 630, déjà présente) — référence relative uniquement.
- `sitemap.ts` : tableau vide au départ (aucune route publiée).
- `robots.ts` : indexation autorisée du site public ; exclusion des futures zones `/admin`, `/compte`, `/panier`, `/commande`. **Les directives `robots.txt` ne remplacent jamais l'authentification ni les contrôles d'accès côté serveur.**

### 4.6 Registre de publication

```ts
// src/types/institutional.ts — proposition
export type InstitutionalSlug =
  | "a-propos" | "contact" | "faq" | "livraison"
  | "retours" | "cgv" | "mentions-legales" | "confidentialite";

export type PublicationStatus = "draft" | "review" | "published" | "archived";

// src/data/institutional/index.ts — proposition
export const institutionalRegistry: Record<InstitutionalSlug, PublicationStatus> = {
  "a-propos": "draft", "contact": "draft", "faq": "draft",
  "livraison": "draft", "retours": "draft", "cgv": "draft",
  "mentions-legales": "draft", "confidentialite": "draft",

```

Le Footer et le `sitemap.ts` lisent ce registre : aucune route non publiée ne peut être liée.

### 4.7 Note RLS (préparation, aucune table créée)

Les tables administratives futures ne devront pas être exposées par une politique RLS publique générale. Privilégier des vues publiques ou des politiques limitées aux colonnes et aux enregistrements effectivement publiables. Les brouillons, données internes et versions non approuvées doivent rester inaccessibles publiquement.

## 5. Correctif minimal de `SiteHeader.tsx` (J13)

**Problème identifié (déduit du code, non mesuré)** : `handleNavClick` sort immédiatement si `pathname !== "/"` ; l'effet d'ancre ne se réexécute pas après une navigation client. Depuis `/faq`, un clic sur « Moto » (`/#category-moto`) peut laisser la cible sous le header sticky.

**Périmètre strict autorisé**
- Corriger uniquement la navigation vers les ancres depuis les autres routes.
- Conserver le comportement actuel depuis l'accueil.
- Tester les navigations client et les liens directs.
- Vérifier le défilement sous le Header sticky (`scroll-margin-top` = hauteur header + 8 px).
- Vérifier le comportement du menu mobile.
- Respecter `prefers-reduced-motion` (aucune animation ajoutée).
- Aucun redesign, aucune modification non nécessaire du Header.

**Approche proposée** : dans `handleNavClick`, si `pathname !== "/"`, laisser `next/link` effectuer la navigation vers `/#anchor` puis, dans un effet dépendant de `pathname` et `hash`, déclencher le défilement avec offset. Alternative : convertir le lien en navigation programmatique. À valider lors de l'implémentation, sans changer l'API du composant.

`SiteHeader.tsx` reste un fichier protégé hors de ce correctif.

## 9. Risques et mitigations

| Risque | Mitigation |
|---|---|
| Régression visuelle de l'accueil lors du déplacement du chrome | captures avant/après, diff visuel |
| Double `<main>` si le gabarit en ajoute un | revue de code + test DOM |
| Prefetch vers une route non publiée | registre unique + `sitemap` vide |
| Correctif d'ancre qui casse l'accueil | tests de non-régression sur `/` obligatoires |
| `metadataBase` absent qui casse OG | pas d'URL absolue inventée ; OG relatif |
